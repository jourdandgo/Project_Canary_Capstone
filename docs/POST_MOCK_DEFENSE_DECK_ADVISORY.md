# Post-mock-defense deck advisory

This is an advisory-only guide. It does not modify the Google Slides deck.

## One prompt to use in Gemini for existing slides

> Redesign this existing slide as if it were created by a senior strategy-consulting presentation designer. Preserve every verified number, chart value, source note, and core message; do not invent data, icons, claims, citations, or decorative charts. Reduce the slide to one clear takeaway, one primary visual, and only the text needed to interpret it. Keep the current dark forest-green / warm-cream palette and serif-plus-sans pairing, but remove template-like card grids, excessive all-caps labels, repeated pills, gradients, and generic AI phrasing. Use deliberate whitespace, a strong editorial headline, consistent left alignment, restrained lines, direct chart labels, and a small source note. Do not turn the slide into an infographic. If a chart is weak, improve hierarchy and annotation rather than fabricating a replacement. The result should feel calm, analytical, specific to a Philippine broiler-farm decision, and hand-crafted—not generically “premium.”

## Main-deck risk score treatment

Keep one short visual in the main deck: four observed checks feed an **observed-concern total**, then an **operational-priority label**. State plainly: “This is a transparent inspection-priority system, not a forecast probability.”

Do not put the full threshold matrix in the main narrative. It interrupts the solution story and invites technical detail before the panel asks for it.

## Appendix sequence for risk-system defense

1. **Why these four checks?** A four-row table: management question, direct observation, and why the dimension remains separate.
2. **How points are assigned.** Show the 0–3 thresholds and the source/provisional status for every dimension.
3. **How the total becomes a label.** Show Low 0–2, Medium 3–5, High 6–8, and Critical 9–12. State that the same total always produces the same label; show evidence coverage separately.
4. **Worked building trace.** Raw value/date → target/reference → calculation → points → total → score-band label → inspection prompt.
5. **Historical audit and limitations.** Coverage, label distribution, missing-environment treatment, and the shadow-pilot validation plan. Do not present correlations as calibration or causality.
6. **Recommendation playbook.** Recorded pattern → inspection prompt → timing → management judgment. State that it never prescribes treatment.

## Defense wording

“We deliberately did not make the risk score a probability model. It is a transparent triage rule. Each point comes from a fact Doc Raymond can verify, and the total maps directly to one published band: 0–2 Low, 3–5 Medium, 6–8 High, or 9–12 Critical. Severe conditions remain visible as problem patterns, and incomplete evidence is flagged separately. During the shadow pilot, we will log each warning, inspection, action, and outcome, then seek farm approval before routine use.”
